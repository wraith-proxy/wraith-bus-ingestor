# Contributing to wraith-bus-ingestor

## Prerequisites

- Python 3.12+
- [`uv`](https://docs.astral.sh/uv/) for dependency management
- Docker, if you're touching anything that runs in the compose stack — this
  repo's own CI never starts, stops, or rebuilds containers
- Access to `ghost-net` (see [Architecture](docs/architecture.md)) if you
  need to run the stack against a live `ghost-site`

## Setup

```bash
git clone https://git.thomaspeoples.com/thomaspeoples/wraith-bus-ingestor.git
cd wraith-bus-ingestor
./bin/setup.sh
```

This syncs dependencies with `uv` and installs the pre-commit hooks.

## Running tests

```bash
./bin/run_tests.sh
```

`run_tests.sh --no-venv` is the same test run against the system
interpreter rather than `uv run`, used by CI. Either way, pytest itself
carries the coverage gate — the threshold is `--cov-fail-under` in
`pyproject.toml`, not hardcoded in the script, so it moves in one place as
coverage improves.

## Code style

Ruff handles formatting and linting; `ty` checks types:

```bash
uv run poe lint
uv run poe format
uv run poe tidy    # both
```

Line length is 99 characters, not ruff's own 79 default — measured against
this codebase's real code, where p99 line length already sits at 99 and the
established voice is long explanatory prose comments (the *why* behind
non-obvious decisions). This codebase comments the **why**, not the what —
a comment restating what the next line does is worth deleting.

## Commits

Commits go through [commitizen](https://commitizen-tools.github.io/commitizen/)
against a custom schema:

```
<type>/TJP-DDMMX: <message>
```

- `type` is one of `feature`, `fix`, `bug`, `break`.
- `TJP-DDMMX` is a ticket-shaped tag: day, month, and a sequence digit —
  not a real issue tracker, just enough structure for commitizen to bucket
  changes into the changelog by type.
- `message` is the summary line, imperative mood, no trailing period.

```bash
uv run cz commit
```

Do not bypass pre-commit hooks with `--no-verify`, and do not hand-edit
`CHANGELOG.md` — it's regenerated by commitizen on version bump.

## dbt changes

Anything under `dbt/models/` should be validated against the data
contracts before it's considered done:

```bash
uv run python contracts/validate.py
```

And, if it touches a model that actually rebuilds, run the real build and
confirm it publishes clean:

```bash
cd dbt && ./build.sh
```

See [`docs/contracts.md`](docs/contracts.md) for what the contracts and
ontology actually assert, and [`dbt/README.md`](dbt/README.md) for the
modelling detail behind each layer.

## Pull requests

- One concern per PR.
- Include or update tests for any behaviour change.
- Run the full pre-commit suite before opening:
  `uv run pre-commit run --all-files`.
- Follow `.gitea/PULL_REQUEST_TEMPLATE.md` — CI runs `bin/run_tests.sh
  --no-venv` and auto-merges once it's green.

## Reporting issues

Open a Gitea issue with what you observed, what you expected, and — for
anything data-shaped — which mart or contract looked wrong and why.
